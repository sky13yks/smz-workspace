## 1. データソース(Phase 1 ペーパーで今すぐ使う)

### 採用構成

| データ | 第一候補 | バックアップ |
|---|---|---|
| 米国株 日足EOD | **Stooq**(実装済みデフォルト・無料・キー不要) | Alpaca Market Data(無料Basic・要APIキー) / yfinance |
| USDJPY 日足 | **Stooq** `usdjpy` | Twelve Data無料枠 / yfinance `JPY=X` |
| 日本株 日足EOD(Phase 3) | **J-Quants API**(JPX公式) | Stooq `XXXX.jp` |

### Stooq(実装済み: `data.StooqProvider`)

- エンドポイント: `https://stooq.com/q/d/l/?s={code}&i=d`(米国株 `spy.us`、日本株 `7203.jp`、FX `usdjpy`)【高: pandas-datareaderソース実物で確認】
- CSV形式 `Date,Open,High,Low,Close,Volume`。**調整済み価格**(分割・配当調整)【中】
- **日次リクエスト上限あり**(具体数非公開。超過時は "Exceeded the daily hits limit" が返る)【中】。
  本システムは12時間キャッシュ+1日1回実行なので41銘柄なら通常問題ないが、
  初回の全銘柄取得やバックテスト準備は時間を分けて行う。
- 【要確認】利用規約(stooq.com/terms.html)の個人利用条件。
- 注意: pandas-datareader 0.11以降はStooq対応を削除済み(本システムは直接CSV取得なので無関係)。

### Alpaca Market Data(バックアップ・将来の第2プロバイダ)

- **ペーパー口座はメールアドレスのみで開設可・無料・KYC不要**(日本からの利用制限は確認されていない)【中】
- 無料Basicプランでも「15分以上前」のヒストリカルバーは**SIP(全市場統合)**データ
  → 日足EOD用途に十分。レート制限200req/分【中】
- 実装する場合: `data.py` にプロバイダを1クラス追加するだけ(インターフェース共通)。

### J-Quants API(日本株・Phase 3)

- JPX公式・合法。**v2 API**(2025-12リリース、v1は2026-06廃止済み)。APIキー認証【高】
- プラン: Free ¥0(**12週遅延**・過去2年 → 開発用) / **Light ¥1,650/月**(遅延なし → 本番用) / Standard ¥3,300 / Premium ¥16,500【高】
- 公式Pythonクライアント `jquants-api-client` 2.x がv2対応。2026-01からCSV提供・分足アドオンあり。
- 【要確認】Lightプランの履歴年数、プラン別レートリミット値。

### 使わないもの

- **Yahoo!ファイナンス(日本)・株探のスクレイピング**: 利用規約で明示的に禁止【高】→ 法令・規約遵守方針により不採用。
- **yfinance**: 非公式(Yahoo米国)。2026年時点も保守は活発(v1.5.1)だがブロック→修正サイクルを
  繰り返しており本番の主データ源には不適。緊急バックアップ扱い【中】。

## 2. 証券会社(Phase 2 実弾で使う)

### 前提となる事実

- 日本株の単元株制度(100株単位)により、20万円では日本株の分散は組めない
  → 実弾Phase 2は**端数株・低単価で分散できる米国株**が合理的(戦略仕様もUSD建て)。
- **税務の分岐が最重要**(§4): 国内業者+特定口座(源泉徴収あり)なら申告不要で完結。
  海外業者は確定申告必須+**損失の3年繰越控除が使えない**(国内業者経由の譲渡のみが繰越の要件)【高】。

### Phase 2 の選定手順(実弾前の宿題)

1. **Webull証券とmoomoo証券に問い合わせ/口座開設**して以下を確認:
   API経由の米国株現物発注可否・端数株可否・**特定口座(源泉徴収あり)がAPI発注に適用されるか**・手数料・レート制限。
2. どちらかが「特定口座×米国株API×端数株」を満たせばそれを採用(税務が最も軽い)。
3. 満たさなければ IBKR(IBSJ): 端数株・API・円入金は確実【高】だが一般口座のみ
   → docs/04 §5 の確定申告フローを受け入れる(台帳がその為の記録を持っている)。
4. いずれも `broker.py` にアダプタ実装 → ペーパー並走2週間 → 最小ロットテスト(docs/02 R8)。

### NISA と自動売買

- kabuステーションAPIは**NISA発注不可が確定**(公式仕様にNISA区分なし・エラー表に
  「NISA発注不可チャネル」の明記)【高】。**唯一の例外候補は立花e支店API**: 注文仕様の
  譲渡益課税区分に「5:NISA」が存在する【高】(実運用でNISA発注が通るかは【要確認】)。
  Webull/moomoo/IBSJのAPI-NISA対応は確認できず【要確認】。
- 現実解: NISA枠は**手動**でコアETF(例: 全世界/S&P500投信・ETF)の積立に使い、
  本システム(課税口座)はそれ以外を運用するハイブリッド。§1-2の積立レバーをNISAで
  実行すれば非課税の複利が取れる。Phase 2開始時にどちらにするか決める(docs/00 §3)。

## 3. 適法性(調査確定・2026-07)

- **高速取引行為者登録は不要**【高】: 金商法上の「高速取引行為」は (a)自動的な売買判断 **かつ**
  (b)取引所への情報伝達時間を短縮する方法(コロケーション等)の両方が要件。
  自宅PC/一般クラウドから通常のインターネット経由で証券会社の公式APIを叩く本システムは
  (b)を満たさず定義上該当しない。(参考: 金商法2条41項、定義府令、金融庁監督指針)
- **自己資金の自動運用に免許・登録は不要**【高】: 投資運用業・助言業は「他人の資産」を扱う業が対象。
- **海外業者の利用自体は違法ではない**【高】(違法なのは無登録業者側の勧誘行為)。
  ただしトラブル時の追及は困難と金融庁が注意喚起 → 国内業者優先の方針と整合。
- **各社約款**: 公式APIの提供社はAPI自動売買を当然許容。公式APIのないWeb画面の自動操作は
  約款違反リスクがあるため行わない。

## 4. 税務(調査確定・2026-07)

- 上場株式等の譲渡益: **申告分離課税 20.315%**(所得税15%+復興特別所得税0.315%+住民税5%)。
  復興特別所得税は2037年まで【高】。
- **国内業者+特定口座(源泉徴収あり)**: API経由の注文も通常注文と同一に処理され、
  口座内で源泉徴収・年間通算 → **原則確定申告不要**【高】。
- **海外業者(Alpaca/IBKR系)**: 特定口座なし → 約定ごとに円換算(TTM等)して損益計算し
  **毎年確定申告**。さらに**配当との損益通算・譲渡損失の3年繰越控除が使えない**
  (国内業者経由の譲渡が要件)【高】← 海外業者の隠れた最大コスト。
- 100万円超の海外送金は国外送金等調書が銀行から税務署へ自動提出される(違法ではない、把握されるだけ)【中】。
- 台帳(ledger.jsonl)のFILLイベントが損益計算の一次資料(docs/04 §5)。
