# リスクポリシー(正典)

このファイルはシステムの**ハードリミットの正典**。コードと齟齬があればバグとして扱う。
各ルールに実装箇所を明記する。

---

## R1. 資金の性質

| ルール | 内容 | 実装 |
|---|---|---|
| R1-1 | 余剰資金のみ。生活費・事業資金の投入禁止 | 運用者の規律(コード外) |
| R1-2 | 借金禁止 = 信用取引・レバレッジ・オプション・レバレッジ型ETF禁止。現物買いのみ | `risk.validate_orders`(現金超過の買い拒否)、`broker.PaperBroker`(現金不足拒否) |
| R1-3 | 空売り禁止 | `risk.validate_orders`(保有超の売り拒否) |

## R2. 注文レベルのガードレール

| ルール | 内容 | 実装 |
|---|---|---|
| R2-1 | ホワイトリスト外の銘柄は売買不可(AIの幻覚・設定ミス対策) | `risk.validate_orders` / `config.toml [universe]` |
| R2-2 | 買付は現金×(1−バッファ1%)まで | `risk.validate_orders` |
| R2-3 | サテライト1銘柄の上限ウェイト10% | `risk.validate_orders` / `strategy.target_weights` |
| R2-4 | 最小約定金額1,000円未満はスキップ(手数料負け防止) | `risk.validate_orders` |

## R3. ポートフォリオレベル(サーキットブレーカー)

判定は毎営業日、時間加重リターン(TWR)指数で行う(入出金の影響を受けない)。

| ルール | 発動条件 | 動作 | 実装 |
|---|---|---|---|
| R3-1 max_drawdown | TWR指数が高値から**-25%** | 全売却 → 停止(HALT)。再開は手動 `resume` | `risk.check_breakers` / `runner.run_daily` |
| R3-2 monthly_loss | 月初から**-10%** | 同上 | 同上 |
| R3-3 hard_floor | 総資産 < **50,000円** | 全停止。`resume --acknowledge` +敗因分析文書化まで再開不可 | 同上 / `cli.resume` |

## R4. フェイルセーフ原則(「わからない時は何もしない」)

| 状況 | 動作 | 実装 |
|---|---|---|
| 価格データ取得失敗(1銘柄でも) | 売買しない。NOTEを台帳に記録 | `data.fetch_all` / `runner.run_daily` |
| 為替取得失敗 | 売買しない | `runner.run_daily` |
| 台帳のハッシュ連鎖が不整合 | 即時エラー停止(自動修復しない) | `ledger.verify_chain` / `runner.run_daily` |
| Claude API失敗/未設定 | AIレビューをスキップしてルールベースで続行 | `advisor.review` |
| 同一営業日の二重実行 | 冪等(何もしない) | `runner.run_daily` |

## R5. AIの権限境界

| ルール | 内容 | 実装 |
|---|---|---|
| R5-1 | AIができるのは**買い注文のveto(取消)と縮小(0.1〜0.9倍)のみ** | `advisor.apply_decisions` |
| R5-2 | 売り注文(リスク低減)をAIは妨害できない | 同上(BUYのみ対象) |
| R5-3 | 銘柄追加・数量増額・設定変更の提案は無視される | 同上(構造的に適用不能) |
| R5-4 | AI判断は全て台帳に記録(モデル名・所感・プロンプトハッシュ) | `runner.run_daily` → AI_MEMOイベント |
| R5-5 | ホワイトリスト外をAIが提案しても発注されない | R2-1が後段で強制 |

## R6. 記録と監査

| ルール | 内容 | 実装 |
|---|---|---|
| R6-1 | 全イベント(入出金・約定・評価・停止・AI判断)を追記専用台帳に記録 | `ledger.append_event` |
| R6-2 | 台帳はSHA-256ハッシュ連鎖で改竄・欠落を検出可能 | `ledger.verify_chain` |
| R6-3 | 台帳は税務(譲渡損益)の一次資料。年1回バックアップ(docs/04) | 運用手順 |

## R7. 変更管理(セルフ・クーリングオフ)

- リスクを**緩める**変更(上限緩和・ブレーカー閾値引き上げ・ユニバース拡大・live化)は:
  1. 変更内容と理由をPRにする
  2. **24時間置く**
  3. 翌日、含み損益を見ずにPRだけを読み直してセルフレビュー → マージ
- リスクを**強める**変更(閾値引き下げ、halt)は即時実行してよい。
- ドローダウン中(-10%超)のリスク緩和変更は**禁止**(判断力が最も落ちている時)。

## R8. 実弾移行の追加条件(Phase 2)

- `mode.trading="live"` はブローカーアダプタ実装+以下が揃うまでコードが起動を拒否する(`broker.make_broker`)。
- 初回発注は最小サイズ(1万円分)で行い、約定・残高照合を目視確認してから全額運用。
- APIキーは `secrets.env`(Git管理外)のみに置く。リポジトリへの書き込み禁止。
